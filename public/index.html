TinyFish 3-Tier Architecture (200 Pts Tier)

How TinyFish Search, Fetch, and Agent work meaningfully in unison

// Complete End-to-End Pipeline Data Flow
User Query: [ Role: "Software Engineer Intern" | Location: "Bangalore" ]
↓ 1. TinyFish Search API (api.search.tinyfish.ai)
↳ Targeted ATS Dork: site:greenhouse.io OR site:lever.co "SWE Intern"
↳ Returns fresh, live candidate job posting URLs
↓ 2. TinyFish Fetch API (api.fetch.tinyfish.ai)
↳ Batch renders JavaScript SPAs via managed Chromium fleet
↳ Strips HTML clutter, returning clean markdown & metadata
↓ 3. TinyFish Agent API (agent.tinyfish.ai/v1/automation/run)
↳ Goal: "Navigate career board, click university openings, extract JSON"
↳ Structured extraction conforming to output_schema
↓ 4. Deduplication & AI Ranking Engine
↳ Merges duplicate postings + scores 0-100% against user skills
1. Search API
api.search.tinyfish.ai

Dynamically discovers live career links across the open web and ATS platforms (Greenhouse, Lever, Ashby, Workday) instead of relying on stale hardcoded URLs.

2. Fetch API
api.fetch.tinyfish.ai

Executes headless Chromium rendering to bypass client-side JavaScript hydration and anti-bot obstacles, extracting clean markdown job descriptions and requirements.

3. Agent API
agent.tinyfish.ai/v1/...

Autonomous "AI That Clicks" for complex, interactive company portals (Workday, Stripe, Uber) that require dropdown filtering, modal clicks, and strict JSON schema output.

Why this scores 200 pts: The 3 endpoints are not padded. Each performs an indispensable layer: Search discovers candidate URLs across ATS hosts, Fetch renders dynamic markdown without client-side lag, and Agent navigates interactive complex single-page apps.
